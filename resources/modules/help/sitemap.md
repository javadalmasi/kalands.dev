## نحوه عملکرد

این ماژول یک sitemap **داینامیک به سبک Yoast SEO** می‌سازد. هیچ فایل استاتیکی روی دیسک نوشته نمی‌شود؛ خروجی XML هنگام درخواست موتور جستجو از دیتابیس ساخته و کش می‌شود.

ساختار خروجی:

```
/sitemap.xml            → ایندکس اصلی (sitemapindex)
  ├─ /product-sitemap1.xml
  ├─ /product-sitemap2.xml
  └─ ...
```

هر زیرـsitemap تا سقف تعیین‌شده URL محصول دارد (پیش‌فرض ۱۰٬۰۰۰). ایندکس اصلی در `/sitemap.xml` قرار دارد و در robots.txt هم به همین آدرس اشاره می‌شود.

## چرا سریع است؟

برای چند میلیون کالا، خواندن «صفحه‌ی ۵۰اُم» با OFFSET بسیار کند است. به‌جای آن، یک جدول سبک متادیتا (`sitemap_shards`) **مرز keyset هر شارد** (اولین و آخرین شناسه‌ی محصول) را نگه می‌دارد. در نتیجه هر زیرـsitemap با کوئری `WHERE id BETWEEN ... ` روی ایندکس کلید اصلی خوانده می‌شود — همیشه فوری، بدون OFFSET کند.

## بازسازی

«بازسازی» فقط متادیتای مرز شاردها را دوباره محاسبه می‌کند (سبک و سریع)، نه میلیون‌ها خط XML. بازسازی **بدون داون‌تایم** است:

1. نسل (generation) جدید کنار نسل فعلی محاسبه می‌شود.
2. pointer نسل فعال به‌صورت اتمیک جابه‌جا و کش پاک می‌شود.
3. نسل قدیمی حذف می‌شود.

بنابراین تا لحظه‌ی پایان بازسازی، sitemap فعلی دست‌نخورده سرو می‌شود.

## زمان‌بندی

- **حالت خودکار:** زمان‌بند سیستم در فاصله‌ی تعیین‌شده (پیش‌فرض هر ۲۴ ساعت) در صورت رسیدن موعد، سایت‌مپ را بازسازی می‌کند.
- **حالت خاموش:** هیچ بازسازی خودکاری انجام نمی‌شود؛ کنترل کاملاً دستی است.
- **کنترل دستی:** از تب «تنظیمات و کنترل» می‌توانید هر زمان بازسازی را دستی شروع، فرآیند در حال اجرا را متوقف، یا با بازنشانی کامل همه‌ی شاردها و کش را حذف کنید.

## بهینه برای موتورهای جستجو

- XML استاندارد با `<lastmod>` واقعی برای هر URL
- ساختار ایندکس چندبخشی (sitemapindex + زیرـsitemapها)
- سرو با هدر درست (`application/xml`)
- فقط محصولات فعال (is_active = true) ایندکس می‌شوند
- آدرس هر محصول به‌صورت `/product/{id}/{slug}`
